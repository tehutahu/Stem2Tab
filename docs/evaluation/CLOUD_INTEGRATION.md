## 今回の実装

- 通常の音声ジョブが完了したら、生成MIDIをダウンロードし直す操作を挟まずに
  `/midi-trial/from-job/:jobId?name=...` から保存MIDIの共通画面へ読み込める。
  完了状態・ジョブID・成果物名を確認してから同じAPIのMIDIを読む。利用者が弦構成を確認し
  インポートを押すまでは変換しない。再推論はせず、元MIDIの内容とハッシュを保持する。
  この画面の `local-midi` はインポート経路の分類で、Basic Pitchの推論が正解という意味ではない。
- 共通画面には原時刻の五線譜/TABと、利用者が明示する運指・量子化・GP5別版への導線がある。
  四分音符のGP5プレビューはリズム非保持と明示。明示リズムGP5は固定の整数BPM・拍子・
  拍原点・格子が必要。元時刻と量子化版の変更量・拒否理由は既存の記録を利用する。
- ホームのナビゲーションから通常採譜、保存MIDI、配置確認付きMuScriptor実験を選べる。
  MuScriptorを既定に昇格せず、非商用条件や資材の配置確認を維持する。
- 型エラー11件を解消した。Reactエントリの型付きimport、テスト関数の明示import、旧ビューアの
  alphaTab型・core設定・loadの使い方を修正。実際のSDKのpaused/stoppedを区別し、旧ビューアも
  読込準備を待ち、エラー後の遅いreadyや差替え前のイベントを拒否する。
- 通常ジョブのポーリングを直列化し、SUCCESS/FAILURE/REVOKEDで止める。ジョブが変わったら
  古いデータを表示せず、古いfetchを中断する。POSTの連打と遅延応答にも世代ガードを付けた。
- 明示リズム生成では、通信中断後も試行IDを保持し、GETで既存結果を確認する。MuScriptorも
  状態確認を止めて同じIDで再開できる。いずれも実際の推論や生成の停止ではない。
  通常ジョブのPOST結果が不明なら二重送信を止め、保存ジョブIDを確認する導線を出す。
  4xxで実行前に拒否された要求は、設定を直して利用者が再送できる。
